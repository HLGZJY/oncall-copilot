# 编码与术语纪律

## 术语纪律

- 命名（变量/函数/文件/issue/测试名）一律用 `CONTEXT.md` 词汇，不漂移到 `_Avoid_` 同义词
- 概念不在术语表里 = 信号：要么在发明不用的语言，要么是真缺口（交给 domain-modeling）
- 与既有 ADR 冲突的输出要显式标出，不静默覆盖
- 首批待敲定术语：事件 vs 告警 / 剧本 / 证据链 / 调查步(step) / 假设 / 降噪 / 指纹 / 干跑 / 确认门 / 恢复验证 / 黄金集 / 命中率

## TDD 接缝规则

- **接缝（seam）= 测试所站的公开边界**；写任何测试前先约定接缝并与用户确认
- 测试只住接缝上，通过公开接口验证行为；期望值必须来自独立真相源（不与实现互为同义反复）
- 红先于绿；一次一片（一个接缝、一个测试、一个最小实现）；重构不属于红绿循环

## 三反模式速查

| 反模式 | 识别信号 |
|---|---|
| 实现耦合 | mock 内部协作者 / 测私有方法 / 重构后测试碎了但行为没变 |
| 同义反复 | 断言用代码同样的方式重算期望值 |
| 横向切片 | 先写完所有测试再写实现（验证的是想象的行为） |

## 深模块词汇（codebase-design，严格使用）

module / interface / implementation / depth / seam / adapter / leverage / locality
四原则：深度是接口的属性；删除测试判透传；接口即测试面；一个 adapter 是假想接缝、两个才是真接缝。
