# 安全护栏

## 三道防线（有效性从强到弱）

| 防线 | 有效性 | 依据 |
|---|---|---|
| 系统层只读接口 / 白名单 | 🟢 最有效 | "MCP 只暴露只读工具，写操作从源头不存在" |
| 人工确认门 | 🟡 有效但会疲劳 | SUSE 做法；Gartner：签核率 2025→2029 从 80% 降至 20% |
| 提示词约束 | ❌ 无效 | "AI 直接把 sudo 命令给换了"（EC2 被删实例案例） |

**白名单 > 黑名单**（白鳝原话依据）：AI 越狱能力强，黑名单会被绕开。
**一句话：约束落在系统层（API/权限/白名单），不落在提示词层。**

## 写操作四道闸门（缺一不可）

```
① 干跑（打印命令+影响面）→ ② 人工确认门（API 层拦截，非提示词）
→ ③ 受控执行（仅 demo 容器内）→ ④ 恢复验证（回查指标，未恢复回退/转人工）
```

## D4 可抄安全清单

MCP 默认关闭（未配令牌返回 404）→ 强令牌 + 作用域 → 只读工具优先 → 调用留痕 + 指纹限流（60 次/分）→ 敏感路径先规范化再拦截 → 审计 HMAC 哈希链 + 双表镜像 → 送模型前脱敏 → 静态数据 AES-256-GCM（加密失败返回空值）

## 操作分级（Pigsty 五级思路）

第 5 级（drop table / drop database / delete cluster）**任何情况下禁止 AI 执行**，只能用户手动。
