## 1. 项目定位（一句话）

> 面向自建服务的 **AI 值班排障智能体**：接入 Prometheus/日志告警后，由大模型**自主决策**完成"降噪分流 → 多源取证 → 根因定位 → SOP 处置（人工确认）→ 恢复验证 → 报告与知识沉淀"，全程**证据链可追溯、效果可评测**。

暂定代号 `oncall-copilot`（英文简历可用：Agentic SRE Copilot / On-call Incident Agent）。

## 2. 解决的痛点与场景

- **痛点**（与云智慧/观测云官网文案同源）：海量重复/误报警告淹没真实故障（告警疲劳）；故障时人工在多系统间切换取证，MTTR 长；专家经验只存在个人脑子里。
- **Demo 场景**：一套 docker-compose 自建业务系统（api-gw → 异步 worker → MySQL/Redis + 日志），配 8+ 种可注入故障剧本；Agent 值班，告警来了自动干活。

## 3. 核心自主决策闭环（项目灵魂，面试第一张图）

```
告警进入 ──► ①分类器(规则+LLM) ──► 误报:归档(记日志)      ┌──────────────────────────────┐
                                    │ 风险:建档观察          │  Agent 主循环（LLM 自主决策）    │
                                    ▼ 真实事件 ────────────► │  观察当前证据 → 提出假设 → 选择   │
 事件上下文(指标/日志/变更/知识) ◄────────── 取证工具 ─────── │  下一步动作(调用工具/查询/执行)  │
       │(PromQL/日志搜索/时序异常/KB检索)                    │  校验结果 → 假设被证实或推翻       │
       ▼                                                    │  失败→回退换假设；超步数→求助人类  │
 ②根因报告(带证据链) ──► ③处置:SOP文档→可执行工具           │  每步 thought/tool/result 落库   │
        │                 (干跑→人工确认→执行→指标验证恢复)    └──────────────────────────────┘
        ▼
 ④复盘:结构化事故报告 ──► 知识库(RAG) ──► 下次同类告警秒级召回历史解法
```

**关键点（防"伪 Agent"指控）**：任务步骤、跳转、终止条件全部由模型在每个 step 依据证据动态决定；固定 SOP 只是 Agent 的"工具"之一，何时调用由模型判断；自带自校验与回退重试。

## 4. 验收标准

| 目标 | 验收口径（目标值，实测后回填，不得虚构） |
|---|---|
| 可复现的真实环境 | docker compose 一键拉起业务系统 + Prometheus/Grafana/Loki + 采集与告警 |
| 故障剧本库 | ≥8 类故障（CPU 飚高/OOM/慢 SQL/死锁/队列堆积/缓存雪崩/下游超时/磁盘满/网络丢包/进程被杀），每个含注入脚本 + 触发告警 + 预标注根因与恢复动作 |
| 告警降噪 | 剧本集内降噪（误报+重复合并）≥80%，**0 漏报**真实事件 |
| 根因定位 | 自主调查 Top-1 命中 ≥70%、Top-3 ≥85%（自建评测口径） |
| 效率与成本 | 单次调查 ≤15 步 / ≤5 分钟 / LLM 成本 ≤¥0.5（便宜模型 + 缓存 + 规则先行） |
| 安全处置 | 写操作 100% 走"干跑 → 人工确认"；处置后自动回查指标验证恢复，未恢复触发回退或求助 |
| 过程可信 | 每一步 thought/tool/input/output 100% 落库，可导出 JSON/Markdown 证据链报告 |
| 评测台 | ≥2 个 LLM × ≥8 剧本矩阵报告（命中率/步数/耗时/成本/失败模式） |
| 可展示 | 3–5 分钟全流程 demo 视频 + README（架构图/演示） + 一页面试架构图 |
| 工程规范 | pytest 单测 + GitHub Actions + Docker Compose，README 可让任何人一键复现 |

## 6. 技术选型

| 层 | 选型 | 理由 / 面试叙事点 |
|---|---|---|
| 语言/后端 | Python 3.11+ / FastAPI（async + SSE） | 复用最强项；后端封装成接口 = 纪律 #2 |
| Agent 编排 | **自研轻量 ReAct 循环**（Planner-Tool-Verifier），基于 OpenAI 兼容 tool-calling + 结构化输出；附一版 LangGraph 对比（附录分支） | 面试讲"框架原理我写过"；可控、可插桩评测 |
| LLM | 推理主用 DeepSeek-chat / Qwen-plus（国产、便宜）；Embedding 用 BGE-M3 或通义 embedding；统一 OpenAI-compatible 抽象可热切换 | 成本叙事 + 评测时做 ≥2 模型对比 |
| 向量库 | Chroma（起步轻）→ 可演进 pgvector | 说明迁移理由即可 |
| 可观测栈 | Prometheus（+node_exporter/prometheus_client 业务指标）、Loki（日志）、Grafana；可选 OTel SDK 埋点 | 补 P5 面试硬通货；PromQL 必会 |
| 存储 | SQLite 起步 → MySQL（事件/证据/报告/评测结果）；Redis（结果缓存/队列） | 复用你已有经验 |
| 执行工具沙箱 | 处置仅在 demo 容器内生效；dry-run/confirm 双门；混沌脚本 Python/bash | 安全护栏叙事 |
| 前端 | Vue3 轻量面板（时间线/证据链/报告） | 复用前端能力，展示层不抢戏 |
| 工程 | Docker Compose 一键起；GitHub Actions：pytest + lint | 与既有 CI 习惯一致，可被验证 |

## 7. 实现步骤（含任务拆解与验收）

### M0 环境与数据底座（0.5–1 天前置 + W1 内）

1. 写 demo 业务系统（可复用你熟悉的 FastAPI + Celery 结构：api-gw 接请求 → worker 消费任务 → MySQL/Redis；暴露 /health、业务指标）。
2. 埋点：prometheus_client 输出 QPS/延迟/队列深度/DB 连接等；日志落盘接 Loki。
3. Prometheus 告警规则 5–8 条（对应剧本）；Grafana 看板 1 张（可选）。
4. 故障注入脚本库（8+）：写 bash/python 注入 CPU/内存/IO/网络/杀进程/慢查询模拟。
5. **验收**：一键拉起，人工触发 CPU 故障 → 能在 Grafana/PromQL 看到异常 → 收到告警。

### M1 告警接入与归一化（W2 前半）

- Webhook 服务、告警指纹（规则+实例+时间窗）、上下文拉取（服务拓扑/近期指标/最近变更）。
- **验收**：同故障重复告警被合并为 1 事件；事件卡片带上下文。

### M2 降噪分类（W2 后半）

- 规则通道（阈值关系/已知误报模式）+ LLM 通道（few-shot）；不确定时落"风险"而非丢弃。
- **验收**：用 3 个剧本验证分类正确，含 1 个"历史上误报的告警"被识别为误报。

### M3 自主根因调查循环 v1（W3，最核心，留足时间）

- 定义工具：①查指标（PromQL 封装）②查日志（Loki 封装）③时序异常检测（统计+IsolationForest）④查知识库（RAG）⑤查变更/拓扑（元数据）⑥执行处置（M5 前先 stub）。
- 自研循环：system prompt（角色/工具说明/输出协议）→ 每轮取证据摘要 → 模型出 `{thought, next_tool, args}` 或 `{conclusion}` → 执行 → 结果摘要入记忆 → Verifier 判断证据是否支持假设 → 步数上限 15。
- 结构化输出解析容错、工具异常重试 2 次、单轮超时保护。
- **验收**：3 个剧本（CPU/慢 SQL/队列堆积）能自主走到结论，输出根因 + 证据路径。

### M4 证据链与过程存储（W4 前半）

- 每步 `{step, thought, tool, input_summary, output_summary, ts, cost}` 落库；事故-证据链模型；导出 JSON/Markdown。
- **验收**：一次完整调查可导出报告，任意一步可回溯原始工具输出。

### M5 处置与恢复验证（W4 后半–W5 前半）

- runbook（Markdown 定义动作与回滚）→ 解析为工具；干跑（打印命令/影响面）→ 确认 API → 执行 → 回查指标验证恢复 → 未恢复自动尝试回滚或转人工。
- **验收**：2 个剧本端到端"自动处置恢复"，全程留痕，写操作全部经过确认门。

### M6 报告与知识库（W5 后半）

- 报告生成（时间线/根因/处置/改进建议）；历史报告切块向量化入库；新告警调查时自动召回相似历史作参考。
- **验收**：复现同一故障第二次，Agent 首步即引用历史案例（可录屏为亮点）。

### M7 评测台（W6）

- 剧本 runner：对每个剧本（预标注根因/期望处置）全自动跑 N 遍；指标：Top-1/Top-3 命中、步数、耗时、成本、失败模式归类；≥2 模型矩阵；每次代码变更跑回归。
- **验收**：评测报告产出（README 挂图），对比 2 模型给出选择理由。

### M8 展示打磨（W6 末）

- README（架构图 + 快速开始 + 评测表）；3–5 分钟 demo 视频；一页面试架构图；简历 bullet 定稿。

## 11. 面试加分点（8 条）

1. **真 Agent**：自主决策闭环 + ≥6 个真实工具 + 自校验 + 回退重试 + 步数上限，不依赖任何 Agent 框架也能讲清原理（附 LangGraph 对比版）。
2. **可信工程**：证据链 100% 落库可导出、写操作人工确认门、只读优先——对齐企业 Agent 上生产的信任前提。
3. **可评测**：自建黄金集（8+ 剧本、预标注根因/处置），输出命中率/耗时/成本矩阵，做模型对比与回归——行业稀缺技能。
4. **真数据**：Prometheus/Loki/OTel + 混沌注入，非玩具数据；架构可换接任何真实系统。
5. **不套壳**：全部自研在开源栈上。
6. **后端工程复用**：FastAPI/异步/Redis/SSE/Docker Compose/GitHub Actions，与校园通知助手一脉相承，面试官不会怀疑是别人代做。
7. **成本叙事**：便宜模型 + 结果缓存 + 分层调用（规则先行、LLM 兜底），单次调查成本可控——对齐企业 ROI 语言。
8. **领域稀缺**：AIOps/可观测是 2026 Gartner 上升词，应届生几乎无人有同款作品。
