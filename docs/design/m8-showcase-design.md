## 定位（先立规矩）

M8 **不是**"高级 UI 可裁剪项"，而是**验收硬口径的可视化载体**。降噪率、漏报、步数/成本、确认门这些数字如果只活在评测 JSON 里，就没有直观出口——裁剪时可以砍交互动效，**六件 P0 信息件不可砍**（对 roadmap 裁剪顺序的修订建议见文末）。

## 目标

- **背景 / 触发原因**：演示与录视频需要一个直观出口，把 M0–M7 的工作效果（降噪、根因、确认门、成本、评测）讲给面试官看；同时用户需要能"模拟使用"真实运维场景。
- **要解决的问题**：① 真实运维场景接入——用户可在面板上选择剧本、注入故障与干扰，模拟一次完整值班；② 智能体工作效果展示——触发问题后，Agent 检测、调查、提请处置的全过程逐步可视化。
- **不做的事（Non-goals）**：不做实时流式 UI 优先于评测台（架构 §8）；不做复杂动效/3D 可视化；不做多用户/权限体系；不做移动端适配；不在 M8 里反推修改 M0–M7 的数据模型（发现缺口回到对应模块修）。

## 演示故事线（信息件取舍的判据）

任何信息件若不在下面这条线里，进 P1 或砍掉：

```
① 混沌控制台注入故障 + 干扰
  → ② 告警流入，实时降噪分诊（误报归档 / 风险观察 / 真实事件）
  → ③ Agent 调查工作台：时间线逐格点亮（thought→工具→摘要→假设变化）
  → ④ 确认门：干跑卡片（命令+影响面）→ 人工确认
  → ⑤ 恢复验证：执行前后指标曲线对比 → 复盘报告 + 历史相似事故召回
  → （事后）⑥ 回放模式：一键重放整场调查
```

## 技术方案

一句话：**Vite + Vue3 + TypeScript + Element Plus + ECharts + SSE**（SSE 通道沿用 `architecture/tech-stack-map.md` L5 已定决策）；前端带 mock 数据开关，页面信息结构可先行于后端开发。

### P0 核心六件（信息结构 / 数据契约 / 交互要点）

#### 1. 混沌控制台

- **信息结构**：剧本下拉（M0 的 8 个剧本，含 1 类业务语义层故障）+ 剧本详情卡（fault_type / 预期根因隐藏不展示）+ **注入按钮** + **干扰开关组**（告警风暴 / 无关误报 / 重复告警）+ 注入状态指示（进行中/已生效/已恢复）。
- **依赖与契约**：M0 注入 API；干扰项由 M0 脚本库提供（支撑 M2"降噪 ≥80% 且 0 漏报"的展示素材——没有干扰，降噪无东西可展示）。
- **交互要点**：注入后跳转/联动到告警流页；状态轮询；干跑性质——不提供"恢复"按钮外的任何写操作。

#### 2. 告警流 + 降噪分诊看板

- **信息结构**：顶部**分诊漏斗**（原始告警数 → 去重聚合后 → 真实事件数，ECharts 漏斗/桑基）+ **"漏报： 0"徽章**（M2 兜底落"风险"的直接可视化）+ 实时告警流列表（SSE 推送，按 fingerprint 聚合折叠）+ 误报归档 / 风险观察两个 tab 列表。
- **依赖与契约**：M1 webhook 去重结果、M2 分类结果；SSE 通道推送新告警与状态变更。
- **交互要点**：点击告警展开指纹/标签/判定理由（规则通道 vs LLM 通道标注）；真实事件卡片点击进入调查工作台。

#### 3. Agent 调查工作台（展示层的心脏）

- **信息结构**：**左列**步骤时间线——每格 = `thought`（Planner 的思考）→ 工具调用（名称+入参摘要）→ `output_summary`（结果摘要）；步骤进行中有呼吸态动画，逐格点亮。**右列**假设看板——confirmed 绿 / rejected 红 / active 黄，每条假设可点击高亮左列中支持它的证据步骤（supporting_steps）与反对步骤（against_steps）。**侧栏成本仪表**——`步数 x/15 · 耗时 m:ss · ¥0.xx`，对照三条红线画进度条（≤15 步 / ≤5 分钟 / ≤¥0.5），逼近红线变警示色。
- **依赖与契约**：M3 的 step 流（SSE 推送新 step）、M4 的 `evidence_steps` / `hypotheses` 表读取；**点击任一步骤可回看原始 `output_json`**（硬规则 5"可回溯"的现场证明）。
- **交互要点**：调查结束后自动出根因结论卡（Top-1 根因 + 置信度 + 证据引用）；步数 ≥10 时被移出上下文的已证伪假设仍可从看板查看（落库不落窗的可视化）。

#### 4. 确认门 + 恢复验证

- **信息结构**：**干跑卡片**——命令全文 + 影响面说明（四道闸门第一道的展示）；**确认 / 拒绝**双按钮（拒绝需填理由，落库）；执行后**恢复验证区**——执行前后指标曲线对比（ECharts 双序列），未恢复显示回退/转人工提示。
- **依赖与契约**：M5 处置 API；确认门在 API 层拦截（硬规则 3——页面只是确认交互的载体，不是权限边界）。
- **交互要点**：确认按钮有二次确认弹窗；整个"干跑→确认→执行→回查"过程在时间线中占独立区段，与调查步骤区分。

#### 5. 事件总览 + 复盘报告页

- **信息结构**：事件列表（severity / status / 根因 / 耗时 / 成本摘要）；报告渲染页（时间线摘要 + 根因 + 证据链引用 + 处置记录）；**底部"召回 N 起历史相似事故"卡片**（M6 RAG 生效的直观证据，点击展开相似度与当时报告）。
- **依赖与契约**：`incidents` 列表查询、报告 API、M6 向量召回结果。
- **交互要点**：报告可导出（markdown/PDF 至少其一）；闭环事件与未闭环分色。

#### 6. 回放模式

- **信息结构**：历史事件列表 → 一键重放；复用调查工作台的布局，按时间轴动画式走步骤（可拖进度条、可暂停）。
- **依赖与契约**：`InvestigationSession` 序列化即重放工件（架构 §4 已有此设计，本页只是它的读取端）。
- **交互要点**：**录视频与现场演示的主通道**——不依赖现场注入成功与否，杜绝演示翻车；回放中同样可点击步骤回看原始输出。

### API 端点草案（⚠️ 全部为草案，实现时随 M1 起逐条校准，不得当契约用）

| API | 方法/通道 | 用途 | 对应信息件 |
|---|---|---|---|
| `/api/scenarios` + `/api/scenarios/{id}/inject` | GET / POST | 剧本列表 / 触发注入（含干扰参数） | 1 |
| `/api/events/stream` | SSE | 告警流、调查 step 流、状态变更推送 | 2、3 |
| `/api/alerts?status=` | GET | 分诊结果列表（deduped/archived/risk/incident） | 2 |
| `/api/incidents` + `/api/incidents/{id}` | GET | 事件列表 / 详情 | 3、5 |
| `/api/incidents/{id}/steps` | GET | 证据链（含原始 `output_json`） | 3、6 |
| `/api/incidents/{id}/hypotheses` | GET | 假设及支持/反对证据引用 | 3 |
| `/api/incidents/{id}/session` | GET | 会话工件（回放用） | 6 |
| `/api/incidents/{id}/actions/{aid}/confirm` | POST | 确认门确认/拒绝（走 M5 四道闸门） | 4 |
| `/api/incidents/{id}/report` | GET | 复盘报告 | 5 |
| `/api/incidents/{id}/similar` | GET | RAG 历史相似事故召回 | 5 |
| `/api/eval/matrix` | GET | 评测矩阵与失败模式分布 | P1-2 |

**写操作说明**：本层唯一写操作是确认门 confirm 与剧本注入，均不绕过 M0/M5 既有闸门；前端不实现任何权限逻辑，确认门的强制力在 API 层（硬规则 3）。

### mock 策略

- dev 模式提供 mock 开关（环境变量 + 请求拦截层）：页面信息结构与交互可先行开发，不等 M3/M4 数据就绪。
- mock 数据形状直接取自 architecture.md §4 六张表，保证切换真实接口时只换数据源不换组件。
- mock 演示版不得出现在 README 挂图与视频中冒充实测效果（硬规则 10）。

## 验收标准（W6 实现后逐条勾选）

- [ ] P0 六件可完整走通一条演示故事线（注入→降噪→调查→确认→恢复→报告→回放）
- [ ] 证据链任一步骤点击可回看原始工具输出（硬规则 5：可回溯）
- [ ] 假设看板三种状态可区分，点击假设可高亮支持/反对证据步骤
- [ ] 成本仪表实时显示步数/耗时/费用并对照三条红线（≤15 步 / ≤5 分钟 / ≤¥0.5）
- [ ] 写操作 100% 走页面确认门交互，拒绝路径可用（确认门拦截在 API 层验证）
- [ ] 回放模式不依赖现场注入即可完整重放历史调查
- [ ] 漏斗图与"漏报： 0"徽章数据来自 M2 真实分类结果，非 mock（README 挂图场景）
- [ ] 全量测试通过；本设计涉及的组件约定接缝有单测
