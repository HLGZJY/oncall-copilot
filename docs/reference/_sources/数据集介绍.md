## 学生项目可用的真实可观测数据来源（按落地成本从低到高排序）
结合你的 `OnCall Copilot` 项目定位，以下所有来源均满足**免费、可复现、学生可操作**，覆盖「直接用的标注数据集 → 一键启动的完整环境 → 批量故障生成工具」三个层级，可对应项目不同阶段的需求。

---

### 一、开箱即用：公开标注数据集（零环境搭建，直接用）
适合阶段：算法验证、模型评测、工具开发初期；不用搭监控栈，直接拿到真实生产场景的指标/日志数据。

| 数据集名称 | 数据类型 | 真实度 | 获取方式 | 适配本项目的场景 |
|---|---|---|---|---|
| **Google Cluster Trace** | 集群级CPU/内存/磁盘IO时序指标、任务调度数据 | 真实生产环境（谷歌数据中心） | 官网免费下载子集（1天/7天/30天） | 验证时序异常检测工具、资源类故障（CPU飚高/OOM/磁盘满）的根因定位算法 |
| **SNAP 微服务故障数据集** | 微服务调用指标、链路追踪、错误日志，附带标注好的10+类故障场景 | 真实微服务系统注入故障采集 | GitHub开源获取 | 根因定位评测的黄金基准集，直接用来测Top-1/Top-3命中率，和业界方法做对比 |
| **LogHub 日志数据集** | HDFS/Spark/Windows/Linux等10+种系统的真实运行日志，含标注异常 | 真实生产系统日志 | 开源免费下载 | 开发日志检索工具、验证日志异常识别、降噪分类模型的日志通道 |
| **Prometheus 官方样例集** | Node Exporter标准主机指标、PromQL样例查询 | 标准生产级指标格式 | Prometheus仓库自带 + Grafana Labs样例 | 练手PromQL封装、开发指标查询工具、验证告警规则逻辑 |

> 补充：这类数据集最大的价值是**用来做算法评测和横向对比**，面试时可以说“我在公开标准数据集上验证了根因算法，命中率XX”，说服力远强于纯自造数据。

### 二、一键启动：成熟开源Demo环境（写最少代码，得真实全栈数据）
适合阶段：端到端Agent开发、完整排障流程验证；是学生项目的最优选择，比完全自研业务系统省80%的工作量，且更贴近真实生产架构。

#### 1. OpenTelemetry Astronomy Shop（官方首选）
- **是什么**：OpenTelemetry 官方出品的微服务电商Demo，包含前端、商品目录、购物车、支付、优惠券等7个服务，覆盖Go/Python/Node.js等多语言。
- **自带能力**：原生全量OTel埋点，自动输出指标、日志、链路追踪数据；自带流量生成器，持续产生真实业务流量；配套Prometheus、Loki、Grafana一键启动。
- **接入成本**：官方提供docker-compose.yml，一条命令拉起全套环境，10分钟就能看到真实的指标和日志。
- **适配本项目**：
  - 直接对接你的告警接入、多源取证模块，不用自己写业务代码和埋点
  - 可以注入各类故障（慢接口、数据库死锁、缓存雪崩、服务宕机），生成完整的故障场景
  - 技术栈完全对齐目标公司（OTel/Prometheus/Loki），面试时叙事更标准

#### 2. Sock Shop（Weaveworks）
- **是什么**：业界最经典的微服务基准Demo，Spring Cloud架构，包含14个服务，完整的电商业务逻辑。
- **自带能力**：支持Prometheus、Zipkin、ELK等全套监控栈接入；社区有大量现成的故障注入方案和评测基准，很多AIOps学术论文都用它做实验环境。
- **适配本项目**：适合用来做更复杂的故障剧本，比如级联故障、服务依赖导致的告警风暴，验证降噪和根因关联能力。

#### 3. 极简自研业务系统（本项目原方案）
- **是什么**：FastAPI + Celery + MySQL/Redis 的简单异步任务系统。
- **优势**：完全可控，想加什么指标、什么故障模式都可以自定义，代码量少，出问题好排查。
- **适配本项目**：适合做核心Agent逻辑的开发调试，环境轻量，启动快，适合每天迭代。

> 本项目最优组合建议：**核心开发用极简自研系统（轻量、可控），评测和演示用OTel Astronomy Shop（标准、有说服力）**，两套环境共用同一套Agent代码，证明架构可迁移。

### 三、故障生成：混沌工程与注入工具（批量生成标注故障剧本）
适合阶段：构建黄金评测集、批量生成故障数据；解决“故障场景少、标注成本高”的问题，自动生成带标注的故障样本。

#### 1. Pumba（轻量Docker级，首推）
- **是什么**：针对Docker容器的轻量混沌工具，一条命令就能给容器注入故障。
- **支持故障**：CPU占用、内存限制、网络延迟/丢包、杀进程、磁盘IO限制。
- **优势**：完美适配docker-compose环境，不用搭集群，学生零门槛上手；命令行调用，可以写成脚本批量自动化执行。
- **适配本项目**：直接用来批量生成8类故障剧本，配合脚本自动触发、自动标注，构建你的黄金评测集。

#### 2. Chaos Mesh（云原生级）
- **是什么**：开源云原生混沌工程平台，支持K8s和Docker，故障类型最全。
- **支持故障**：Pod故障、网络故障、文件系统故障、内核故障、时间偏移等。
- **适配本项目**：如果后续想扩展K8s场景，可以用它生成更复杂的故障；面试时提一句“兼容Chaos Mesh做混沌注入”，专业度会提升。

#### 3. Locust / k6（流量型故障生成）
- **是什么**：开源压测工具，模拟用户流量，制造高负载场景。
- **适配本项目**：用来生成队列堆积、CPU飚高、连接数打满等流量型故障，比单纯用死循环占CPU更贴近真实业务场景。

#### 4. 自定义注入脚本
- **是什么**：自己写bash/python脚本，比如慢SQL语句、死循环、删缓存、杀进程。
- **优势**：最灵活，可以精准控制故障强度和触发时机，方便做精准标注。
- **适配本项目**：配合上述工具使用，补充业务层故障（比如慢SQL、缓存雪崩）。

### 四、补充：免费云服务与沙箱
适合阶段：体验商业产品形态、验证跨环境迁移能力；不建议作为主力数据来源。
1. **Grafana Cloud 免费版**：免费额度足够学生使用，可以把本地指标日志同步上去，体验云原生可观测的完整形态。
2. **观测云个人免费版**：可以体验商业AIOps产品的交互和功能设计，参考其界面和能力边界，但不适合作为自研项目的数据底座。

### 五、结合本项目的落地建议（对应M0阶段）
基于上述资源，给你调整优化M0阶段的执行路径，兼顾速度、真实性和说服力：

#### 第一步（2天）：跑通最小环境
用官方OTel Astronomy Shop的docker compose一键拉起业务+监控栈，确认：
- Prometheus能拿到指标，Grafana能看到看板
- Loki能收集到服务日志
- 手动触发一个简单故障（比如停掉支付服务），能收到Prometheus告警

#### 第二步（3天）：搭建故障注入能力
组合使用 **Pumba + 自定义SQL脚本 + Locust**，实现5类核心故障的一键注入：
- 资源类：CPU飚高、内存溢出（Pumba）
- 网络类：下游超时、网络丢包（Pumba）
- 业务类：慢SQL、数据库死锁（自定义脚本）
- 负载类：队列堆积、连接数打满（Locust）
- 故障类：进程被杀、缓存雪崩（Pumba + 自定义脚本）

#### 第三步（2天）：生成第一版黄金评测集
每个故障剧本跑3次，记录：
- 触发时间、恢复时间
- 触发的所有告警（数量、内容、时间）
- 标准根因、标准排查路径、标准处置方法
输出结构化的标注文件，作为后续M3、M7的评测基准。

### 关于“数据自造”质疑的统一回应口径
这是学生做这类项目必被问的问题，提前准备好标准答案：
> “这个Demo环境是自建的，但监控栈（Prometheus/Loki/OTel）、故障模式、指标格式和生产环境完全一致，Agent的核心逻辑、工具封装、决策流程都和接入真实生产系统没有区别。整套架构只需要替换告警接入地址和指标标签，就能迁移到任何支持Prometheus的真实环境中。我用开源标准Demo和混沌工具生成评测集，就是为了保证评测口径透明、可复现，避免过拟合。”
